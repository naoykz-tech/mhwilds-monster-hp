# 学習中の質問と答え

## REFramework・ゲームの調べ方

**Q. TDB Methods とは？**
TDB は Type DataBase（型のデータベース）。ゲームの中にどんなクラスがあり、何ができるかの名簿。TDB Methods はそのクラスにできること（メソッド）の一覧、TDB Fields は持っているデータ（フィールド）の一覧。

**Q. app.cPlayerManageInfo が大量に出てくるが、何を探せばいい？**
app.cPlayerManageInfo はメソッドの名前ではなく、メソッドが返すものの種類（ハンター1人分の情報）。その行のメソッド名の部分を見て、カッコの中が空のものを探す。

**Q. カッコの中に System.Guid や System.Int32 があるメソッドは？**
「どの人か」を指定する情報（引数）が必要なメソッド。番号（Int32）や ID（Guid）を渡す必要があるので、自分のプレイヤーを取るときは対象外。

**Q. 調べている間にモンスターに襲われる**
ベースキャンプや拠点など、モンスターが来ない安全な場所で調べる。

**Q. Steam を経由せずにゲームフォルダを開くには？**
エクスプローラーのアドレスバーにパスを入力するか、autorun フォルダをクイックアクセスにピン留めする。

## Lua の書き方

**Q. local とは？**
「自分のパソコン」という意味ではなく、新しく箱（変数）を作るときに付ける言葉。その箱はこのあたりのコードの中だけで使う、という宣言。

**Q. pm とは？**
app.PlayerManager を入れておく箱に、自分で付けた名前。PlayerManager の頭文字。

**Q. sdk とは？**
ソフトウェア開発キットの略。REFramework が用意している、ゲームの中身を触るための道具箱。

**Q. get_managed_singleton とは？**
Object Explorer の Singletons 一覧から、名前で1つ取ってくる道具。シングルトンは「ゲームの中に1つしかない係」のこと。

**Q. nil とは？ null と違う？**
どちらも「空っぽ」という意味。JavaScript などでは null、Lua では nil と書く。

**Q. = と == の違いは？**
= は「右のものを左の箱に入れる」、== は「同じかどうか比べる」。ほとんどのプログラミング言語で共通のルール。

**Q. ~= とは？**
「等しくない」という意味（Lua の書き方）。JavaScript や Python では != と書く。

**Q. なぜ "getMasterPlayer" をダブルクォーテーションで囲む？**
囲むと「ただの文字」になる。call にはメソッド名を文字として渡すルール。囲まないと、その名前の箱を探してエラーになる。

**Q. if の文は改行しないといけない？**
改行しなくても動く。ただし読みやすいように改行して書くのがおすすめ。

**Q. なぜモンスターの前にプレイヤーの情報を取るの？**
プレイヤーは画面にいつもいて確認しやすいから。それに、「係を呼んでメソッドで情報を取り出す」流れはモンスターでも同じなので、その練習になる。

## つまずいたこと

**Q. Player OK が Reset Scripts の瞬間だけ出て消える**
コードが re.on_frame の end) より外に書かれていた。外に書くと読み込み時に1回しか動かない。end) をいちばん最後に移動して解決。

**Q. 英語キーボードで Shift + ハイフンを押すと = が出る**
Windows がキーボードを日本語配列だと認識していたため。キーボードの設定を英語配列に変えて解決。

## 2026-11-28 に質問したこと

### Object Explorer の調べ方

**Q. メソッドの行を開くと Virtual Index や Flags が出てくる。これは中身？**
違う。それはメソッド自体の説明書き。本物の中身（データ）を見るときは TDB Fields（フィールド）からたどる。

**Q. PlayerCatalogHolder は関係ある？**
名前からすると、見た目や装備の一覧をまとめた係。座標を探すときは関係なかった。

**Q. 「0x10 Object k__BackingField」のどこがフィールド名？**
`<Object>k__BackingField` の部分。前後の `<` `>` も名前の一部。0x10 は場所を表す番号なので名前には入れない。C# が自動で付けた名前なので変わった形になっている。

**Q. Transform を開くとまた via.Transform や via.Component が出てくる。どこを見る？**
via.Transform が本体。座標（Position）は Reflection Properties の中にある。via.Component は Transform の元になる大もとの種類なので見なくてよい。

**Q. Position の Variable を開いても数字が出ない**
座標のような「値型」は Object Explorer では数字が表示されないことがある。Size 24 は数字3つ分（X・Y・Z）の大きさという意味。数字はコードで取り出して確かめる。

**Q. モンスターを調べるとき、まず何をする？**
モンスターがいる場所に行く。近くにいないとリストが空っぽのことがある。ただし調べものは襲われにくい場所で。

**Q. 名前が ace. で始まっているけどいい？**
大丈夫。ace はカプコンのゲームエンジンで使われている名前の一部で、app. と同じくゲームの正式な名前。

**Q. ヌルポインター（null pointer）とは？**
「空っぽ」という意味。Lua の nil と同じ。その枠には今モンスターが入っていない。

**Q. リストを開くと 700 や Capacity 700 と出る。700体いるの？**
いない。700 は用意されている枠の数。中身が入っている数は ValidIndexManager の Count（このときは189）で、中身はとびとびの番号に入っている。

**Q. _items の中を開くと「VAL TYPE」と出て数字が見えない**
中身が数字そのもの（値型）なので、Object Explorer では見えない。ここから先はコードで調べるほうが早い。

### Lua の書き方

**Q. get_Transform とは？**
`go`（ハンターの体）についている Transform（位置・向き・大きさを管理する部品）を取ってくるメソッド。RE Engine では部品を取り出すメソッドは「get_ + 部品の名前」の形が多い。

**Q. local tr / local pos の tr や pos とは？**
自分で付けた箱の名前。Transform の頭文字で tr、Position の頭文字で pos。pm と同じで、何という名前でも動く。

**Q. 座標の Y と Z が細かく動き続けるけどいいの？**
いい。座標は小数で管理されていて、立っているだけでも体の揺れで細かく動く。RE Engine では Y が高さ。

**Q. 小数点以下が目まぐるしく変わって読めない**
`string.format("X:%.1f Y:%.1f Z:%.1f", pos.x, pos.y, pos.z)` のように書くと、小数点以下1桁にそろえられる。`%.1f` が「小数点以下1桁まで」という意味。

**Q. .. とは？**
文字と数字をつなげる記号（Lua 独特の書き方）。

**Q. if arr == nil then return end は「もう一度繰り返せ」という意味？**
違う。return は「ここで終わる」という意味。配列が取れなかったら、この先には進まずに止める安全装置。

**Q. for とは？ i とは？**
for は「繰り返す」。`for i = 0, arr:get_size() - 1 do 〜 end` は、i を0から最後の番号まで1つずつ増やしながら繰り返す。i は「今何番目を見ているか」の番号を入れる箱で、インデックスの頭文字。
たとえるなら、700個の下駄箱を0番から順に開けていき、靴（モンスター）が入っていたら count に1を足す、という動き。

**Q. 行の先頭のスペースはそろえないといけない？**
Lua はスペースの数を気にしないので、ずれていても動く。読みやすさのために、`if` や `for` の中の行はスペース4つ分右に下げるのがルール。`re.on_frame(function()` と最後の `end)` は左端。VS Code では Tab で右、Shift + Tab で左に動かせる。

### つまずいたこと

**Q. 「hello.lua:12: unfinished string near ...」と出る**
12行目の最後に `")` が1組余分に付いていた。余分な `"` を「新しい文字の始まり」と思って、閉じる `"` を探しに行ってエラーになる。余分な2文字を消して解決。

**Q. 「hello.lua:40: unexpected symbol near ...」と出る**
最後の `end)` より下に、前のコードの残りが残っていた。`end)` より下を全部消して解決。

**Q. for の行を書き忘れた**
`for ... do` の行と、それを閉じる `end` が抜けると、i が空っぽのままでエラーになる。for と if は、それぞれ自分の `end` が必要。

**Q. GitHub Desktop でコミットしたのに GitHub に届いていない**
コミットしただけでは自分のパソコンの中にしか保存されない。Push origin を押して初めて GitHub に送られる。
